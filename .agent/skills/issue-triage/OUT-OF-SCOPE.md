# Out of Scope

The `.out-of-scope/` directory records concepts and capabilities that are explicitly out of scope for this project. When triaging, check this directory before applying `wontfix`.

## Format

One file per concept (not one file per issue). File name is a kebab-case slug of the concept.

```
.out-of-scope/
  multi-tenancy.md
  mobile-app.md
  real-time-collaboration.md
```

## File structure

```markdown
# <Concept name>

<Why this is out of scope — 1–3 paragraphs. Include rationale, constraints, and
any past decisions (ADRs) that inform the decision. May include code examples
if that helps explain the boundary.>

## Prior requests

- #<issue number> — <one-line summary>
- #<issue number> — <one-line summary>
```

## When to create an out-of-scope file

Create a file when:
- An issue is being closed `wontfix` for a reason that applies to a class of requests, not just this one issue
- The same request has come up more than once
- The decision is non-obvious (would benefit from documented rationale for future triagers)

Don't create a file for trivial one-offs.

## When to reference an out-of-scope file

In the triage comment on a `wontfix` issue, link to the relevant file:

> *This was generated by AI during triage.*
>
> This request is out of scope. See `.out-of-scope/multi-tenancy.md` for rationale.
