## Module Hierarchy

### Decision Tree

```
Is this environment-specific (has real values, backend config)?
  └─ YES → Composition  (environments/prod/, environments/dev/)

Does it combine multiple infrastructure concerns?
  └─ YES → Infrastructure Module  (modules/web-application/)

Is it a focused, reusable group of related resources?
  └─ YES → Resource Module  (modules/vpc/, modules/database/)
```

### Type Reference

| Type | Reusable | Has backend.tf | Has tfvars | Example |
|------|----------|----------------|------------|---------|
| Resource Module | ✅ highly | ❌ | ❌ | `modules/vpc/`, `modules/rds/` |
| Infrastructure Module | ✅ moderately | ❌ | ❌ | `modules/web-stack/` |
| Composition | ❌ env-specific | ✅ | ✅ | `environments/prod/` |

### Standard Layout

```
.
├── environments/
│   ├── prod/
│   │   ├── backend.tf          # Remote state config (ONLY here)
│   │   ├── main.tf             # Module calls
│   │   ├── variables.tf
│   │   ├── outputs.tf
│   │   ├── versions.tf
│   │   └── terraform.tfvars    # Real values (ONLY here, git-ignored for secrets)
│   ├── staging/
│   └── dev/
├── modules/
│   ├── vpc/                    # Resource module
│   ├── compute/                # Resource module
│   ├── database/               # Resource module
│   └── web-stack/              # Infrastructure module (uses above)
└── examples/
    ├── minimal/                # Least-config example (doc + test fixture)
    └── complete/               # All options enabled
```

`examples/` serves as both documentation and integration test fixtures.

## Full Module Scaffold

Create exactly these five files per module:

### `versions.tf`

```hcl
terraform {
  required_version = ">= 1.6.0"

  required_providers {
    # Add only providers this module directly uses
    aws = {
      source  = "hashicorp/aws"
      version = ">= 5.0"        # modules use >= lower bound; root pins tighter
    }
  }
}
```

### `variables.tf`

```hcl
variable "name" {
  description = "Name prefix for all resources in this module"
  type        = string
}

variable "environment" {
  description = "Deployment environment (dev / staging / prod)"
  type        = string

  validation {
    condition     = contains(["dev", "staging", "prod"], var.environment)
    error_message = "Must be one of: dev, staging, prod."
  }
}

variable "tags" {
  description = "Tags applied to all resources"
  type        = map(string)
  default     = {}
}

# ── resource-specific variables below ─────────────────────────────────────
```

**Rules:**
- Every variable: `description` → `type` → `default` → `sensitive` → `nullable` → `validation`
- Never omit `description` or `type`
- Mark secret inputs `sensitive = true`
- Use `optional()` for object attributes with sensible defaults (Terraform 1.3+)

### `main.tf`

```hcl
locals {
  name_prefix = "${var.name}-${var.environment}"
  common_tags = merge(var.tags, {
    Module      = "terraform-<module-name>"
    ManagedBy   = "terraform"
    Environment = var.environment
  })
}

resource "aws_<resource>" "this" {
  count = var.create_<resource> ? 1 : 0   # feature-flag first

  name = local.name_prefix
  tags = local.common_tags

  # resource-specific arguments
}
```

### `outputs.tf`

```hcl
output "id" {
  description = "Resource ID"
  value       = try(aws_<resource>.this[0].id, null)
}

output "arn" {
  description = "Resource ARN"
  value       = try(aws_<resource>.this[0].arn, null)
}

# Sensitive outputs
output "connection_string" {
  description = "Connection string"
  value       = try(aws_<resource>.this[0].endpoint, null)
  sensitive   = true
}
```

Minimum required: `id` + cloud identifier (`arn` / `urn` / `self_link`). Mark secrets `sensitive = true`.

### `README.md`

Required for any published or shared module:

```markdown
# terraform-<module-name>

Brief description.

## Usage

\`\`\`hcl
module "<name>" {
  source      = "./modules/<name>"
  name        = "my-app"
  environment = "prod"
  tags        = { Team = "platform" }
}
\`\`\`

## Requirements

| Name | Version |
|------|---------|
| terraform | >= 1.6.0 |
| <provider> | >= X.Y |

## Inputs / Outputs

(auto-generated by terraform-docs)
```

## Wiring into Root

### Step 1 — `variables.tf`: feature flag + config inputs

```hcl
variable "create_<name>" {
  description = "Set to true to create the <name> resource"
  type        = bool
  default     = false
}

variable "<name>_instance_class" {
  description = "<Resource> instance class"
  type        = string
  default     = "<default>"
}
```

### Step 2 — `main.tf`: module call with feature flag

```hcl
module "<name>" {
  source = "./modules/<name>"
  count  = var.create_<name> ? 1 : 0

  name        = "${var.project}-<suffix>"
  environment = var.environment
  tags        = var.tags
}
```

Depends on another conditional module? Guard both:

```hcl
module "db_replica" {
  source = "./modules/db-replica"
  count  = var.create_db_replica && var.create_database ? 1 : 0

  primary_id = module.database[0].id
}
```

### Step 3 — `locals`: aggregate computed identifiers

```hcl
locals {
  vpc_id = var.create_vpc ? module.vpc[0].vpc_id : var.existing_vpc_id

  # Collect all resources for grouping / policy attachment
  all_instance_arns = compact(concat(
    var.create_compute ? module.compute[0].instance_arns : [],
    var.create_batch   ? module.batch[0].instance_arns   : [],
  ))
}
```

`compact()` removes null/empty. `concat()` merges lists. `distinct()` deduplicates.

### Step 4 — `outputs.tf`: expose key attributes

```hcl
output "<name>_id" {
  description = "<Resource> ID, null when not created"
  value       = try(module.<name>[0].id, null)
}
```

## Cross-Module Dependency Patterns

### Parent → child: pass IDs

```hcl
module "security_group" {
  source = "./modules/security-group"
  count  = var.create_security_group && var.create_vpc ? 1 : 0

  vpc_id = module.vpc[0].vpc_id
  name   = var.project
}
```

### Cross-stack: remote state (only at true ownership boundaries)

Use `terraform_remote_state` **only** when:
- Different teams own the two stacks, OR
- Different release cadences mean the stacks change independently

```hcl
data "terraform_remote_state" "networking" {
  backend = "s3"
  config = {
    bucket = "my-terraform-state"
    key    = "prod/networking/terraform.tfstate"
    region = "us-east-1"
  }
}

# Consume in current stack
module "compute" {
  source     = "./modules/compute"
  vpc_id     = data.terraform_remote_state.networking.outputs.vpc_id
  subnet_ids = data.terraform_remote_state.networking.outputs.private_subnet_ids
}
```

When you control both stacks, wire via module outputs instead — avoid hidden cross-stack coupling.

### Locals for deletion-order dependencies

Using `try()` in a local to prefer a conditional resource's attribute forces correct deletion order:

```hcl
locals {
  # VPC + secondary CIDR associations + subnets — explicit ordering
  vpc_id = try(
    module.secondary_cidr[0].vpc_id,
    module.vpc[0].vpc_id
  )
}
```

## Testing Strategy

### Decision Matrix

| Situation | Approach | Tools |
|-----------|----------|-------|
| Syntax + formatting | Static | `fmt`, `validate` |
| Best practices + provider rules | Linting | `tflint` |
| Security / compliance | Policy scan | `trivy`, `checkov`, OPA |
| Module logic, input/output | Native tests | `terraform test` (1.6+) |
| Real infrastructure validation | Integration | Terratest (Go) |
| Cost before apply | Cost estimation | Infracost |

### Native Tests (1.6+) — patterns

```hcl
# tests/vpc.tftest.hcl
run "vpc_created_with_correct_cidr" {
  command = plan

  assert {
    condition     = aws_vpc.this.cidr_block == var.vpc_cidr
    error_message = "VPC CIDR must match input variable"
  }
}

run "private_subnets_exist" {
  command = apply   # required for computed values (subnet IDs, ARNs)

  assert {
    condition     = length(aws_subnet.private) == length(var.azs)
    error_message = "One private subnet per AZ expected"
  }
}
```

**Critical rules:**
- `command = plan` — safe for input-derived values only
- `command = apply` — required for computed values AND set-type blocks
- Set-type blocks: use `for` expressions or `one()`, never `[0]`

### Mock providers (1.7+) — free integration tests

```hcl
# tests/mocks/aws.tfmock.hcl
mock_provider "aws" {
  mock_resource "aws_vpc" {
    defaults = {
      id         = "vpc-mock12345"
      arn        = "arn:aws:ec2:us-east-1:123456789012:vpc/vpc-mock12345"
      cidr_block = "10.0.0.0/16"
    }
  }
}
```

```hcl
# tests/unit.tftest.hcl
provider "aws" {}  # resolved to mock

run "test_naming" {
  command = plan

  assert {
    condition     = aws_vpc.this.tags["Name"] == "myapp-prod"
    error_message = "VPC Name tag must follow naming convention"
  }
}
```

### Terratest (Go) — real infra

```go
func TestVPCModule(t *testing.T) {
    t.Parallel()

    opts := &terraform.Options{
        TerraformDir: "../../examples/complete",
        Vars: map[string]interface{}{
            "name":        "test-vpc",
            "environment": "dev",
        },
    }

    defer terraform.Destroy(t, opts)
    terraform.InitAndApply(t, opts)

    vpcID := terraform.Output(t, opts, "vpc_id")
    assert.NotEmpty(t, vpcID)
}
```

## Anti-Patterns

| Anti-Pattern | Problem | Fix |
|-------------|---------|-----|
| `terraform.tfvars` in a module | Hard-codes values, breaks reuse | Move to `environments/<env>/` |
| `backend.tf` in a module | Can't be reused in different backends | Move to composition |
| `depends_on` on whole modules | Forces serialization, hides intent | Pass attributes explicitly |
| `count` for maps/named resources | Index churn on add/remove | Use `for_each` |
| Flat 2000-line root config | Slow plans, full blast radius | Split by concern into modules |
| `terraform_remote_state` everywhere | Hidden cross-stack coupling | Wire via module outputs when same team |
| Secrets in variable defaults | Leaks to `.terraform.lock.hcl`, logs | Use Secrets Manager / Vault |
| Omitting `README.md` | Module unusable without docs | Always include usage example |

## Pre-Commit Checklist

**Module files**
- [ ] `main.tf` — resource label `this` for primary singleton; `count`/`for_each` first
- [ ] `variables.tf` — every variable has `description` + `type`; no secrets in defaults
- [ ] `outputs.tf` — exports `id` + provider identifier minimum; secrets `sensitive = true`
- [ ] `versions.tf` — `required_version` + all providers with version constraints
- [ ] `README.md` — usage example present

**Root wiring**
- [ ] `create_<name>` bool added to root `variables.tf` with `default = false`
- [ ] Module block uses `count = var.create_<name> ? 1 : 0`
- [ ] Dependent modules guard `count` with both feature flags
- [ ] Root `outputs.tf` uses `try(module.<name>[0].<attr>, null)` pattern
- [ ] `terraform.tfvars` only at composition level
- [ ] `backend.tf` only at composition level

**Validation**
- [ ] `terraform fmt -recursive` exits 0
- [ ] `terraform init -backend=false && terraform validate` exits 0
- [ ] `tflint` exits 0
- [ ] `trivy config .` or `checkov -d .` passes (or findings documented)
- [ ] `terraform plan` runs clean with representative inputs
