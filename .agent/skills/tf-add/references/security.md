## Secrets Management

### Never in Terraform state

The following **always** persist to state regardless of `sensitive = true`:

- Data source values read at plan time (e.g., `aws_secretsmanager_secret_version.secret_string`)
- Resource arguments that are not `write-only`
- Random passwords generated by `random_password` (in state as plaintext)

### Correct patterns by secret type

**Passwords / tokens — use write-only (Terraform 1.11+)**

```hcl
# Injects the value but never stores it in state
resource "aws_db_instance" "this" {
  # ...
  password_wo         = var.db_root_password       # write-only arg
  password_wo_version = var.db_password_version    # bump to trigger rotation
}

variable "db_root_password" {
  description = "Root password injected via CI env var — not stored in state"
  type        = string
  sensitive   = true
}
```

**Credentials read from Secrets Manager — use ephemeral (Terraform 1.10+)**

```hcl
ephemeral "aws_secretsmanager_secret_version" "db_creds" {
  secret_id = "prod/database/credentials"
}

resource "aws_db_instance" "this" {
  password = ephemeral.aws_secretsmanager_secret_version.db_creds.secret_string
  # ^ never written to state
}
```

**Retrieving a secret via data source (pre-1.10) — mark sensitive**

```hcl
data "aws_secretsmanager_secret_version" "db_creds" {
  secret_id = "prod/database/credentials"
}

locals {
  db_password = jsondecode(data.aws_secretsmanager_secret_version.db_creds.secret_string)["password"]
}
```

⚠️ **LLM mistake:** Even with `sensitive = true`, the value is persisted to state. Use `ephemeral` resources (1.10+) or `write-only` arguments (1.11+) when the resource supports them.

### Supply secrets via environment — never as variable defaults

```bash
# CI/CD: inject at plan/apply time
export TF_VAR_db_root_password="${DB_PASSWORD}"

# Or pass as -var flag
terraform plan -var="db_root_password=${DB_PASSWORD}" -out=tfplan
```

In `terraform.tfvars` — **never** include secrets. Use `terraform.tfvars` only for non-secret configuration.

### Vault integration (provider-agnostic)

```hcl
data "vault_generic_secret" "db_creds" {
  path = "secret/prod/database"
}

resource "aws_db_instance" "this" {
  password = data.vault_generic_secret.db_creds.data["password"]
}
```

## Sensitive Variables & Outputs

### Variables

```hcl
variable "api_token" {
  description = "API token — supply via TF_VAR_api_token env var, never in tfvars"
  type        = string
  sensitive   = true
}

variable "database_config" {
  description = "Database configuration including credentials"
  type = object({
    host     = string
    port     = number
    username = string
    password = optional(string)  # supply via TF_VAR, not defaults
  })
  sensitive = true
}
```

### Outputs

```hcl
output "db_connection_string" {
  description = "Database connection string"
  value       = "postgresql://${var.db_user}:${var.db_password}@${aws_db_instance.this.endpoint}/${var.db_name}"
  sensitive   = true
}
```

`sensitive = true` on an output:
- Redacts value in `terraform plan` / `terraform apply` output
- Still readable via `terraform output -raw db_connection_string`
- Still stored in state (encrypt state backend)

## State File Security

### Why state is sensitive

State contains:
- All resource attributes (including computed secrets like connection strings, private keys if not `write-only`)
- Provider credentials if injected via resource arguments
- Contents of `data` source reads

### Minimum security requirements

1. **Encrypt at rest** — use backends with server-side encryption (S3 + KMS, Azure Blob CMK, GCS CMEK)
2. **Restrict access** — least-privilege IAM on the state bucket; developers should not have `s3:GetObject` on prod state directly
3. **Enable versioning** — allows recovery from bad applies
4. **Enable audit logging** — CloudTrail, Azure Monitor, GCS audit logs on the state bucket
5. **Lock writes** — use backend locking to prevent concurrent applies

### Encryption configuration examples

**AWS S3 + SSE-KMS**

```hcl
resource "aws_s3_bucket_server_side_encryption_configuration" "state" {
  bucket = aws_s3_bucket.terraform_state.id

  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm     = "aws:kms"
      kms_master_key_id = aws_kms_key.terraform_state.arn
    }
    bucket_key_enabled = true
  }
}
```

**Azure Blob (CMK)**

```hcl
resource "azurerm_storage_account" "state" {
  name                     = "mytfstate${var.environment}"
  resource_group_name      = azurerm_resource_group.state.name
  location                 = var.location
  account_tier             = "Standard"
  account_replication_type = "GRS"

  blob_properties {
    versioning_enabled = true
  }

  identity {
    type = "SystemAssigned"
  }
}
```

### State access IAM policy (AWS example)

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "TerraformStateReadWrite",
      "Effect": "Allow",
      "Principal": { "AWS": "arn:aws:iam::ACCOUNT:role/terraform-apply" },
      "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::my-tf-state-bucket/prod/*"
    },
    {
      "Sid": "TerraformStateLock",
      "Effect": "Allow",
      "Principal": { "AWS": "arn:aws:iam::ACCOUNT:role/terraform-apply" },
      "Action": ["dynamodb:GetItem", "dynamodb:PutItem", "dynamodb:DeleteItem"],
      "Resource": "arn:aws:dynamodb:us-east-1:ACCOUNT:table/terraform-locks"
    }
  ]
}
```

## IaC Scanning Tools

### trivy (preferred — broad coverage)

```bash
# Scan Terraform configs for misconfigurations
trivy config .

# With severity filter
trivy config . --severity HIGH,CRITICAL

# Output as SARIF for GitHub Advanced Security
trivy config . --format sarif --output trivy-results.sarif
```

### checkov

```bash
# Full scan
checkov -d . --framework terraform

# With specific checks enabled/disabled
checkov -d . --check CKV_AWS_18,CKV_AWS_21 --skip-check CKV_AWS_144

# Output as JUnit (for CI)
checkov -d . --output junitxml --output-file checkov-results.xml
```

### tflint

```bash
# Initialize plugins
tflint --init

# Run with provider plugin (e.g. AWS)
tflint --enable-plugin=aws

# Config file
cat > .tflint.hcl <<'EOF'
plugin "aws" {
  enabled = true
  version = "0.27.0"
  source  = "github.com/terraform-linters/tflint-ruleset-aws"
}

rule "terraform_deprecated_interpolation" { enabled = true }
rule "terraform_unused_declarations" { enabled = true }
EOF
```

### Pre-commit integration

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/antonbabenko/pre-commit-terraform
    rev: v1.92.0
    hooks:
      - id: terraform_fmt
      - id: terraform_validate
      - id: terraform_tflint
        args:
          - --args=--config=__GIT_WORKING_DIR__/.tflint.hcl
      - id: terraform_trivy
      - id: terraform_checkov
        args:
          - --args=--framework terraform
          - --args=--skip-check CKV_AWS_144   # document skips
```

### Inline suppression (document the reason)

```hcl
#checkov:skip=CKV_AWS_144: Cross-region replication not required for this non-production cache bucket
resource "aws_s3_bucket" "app_cache" {
  bucket = "myapp-cache-${var.environment}"
}
```

## Least-Privilege IAM Patterns

### Principle

Terraform CI/CD role should have only the permissions needed for the current workload. Never use `AdministratorAccess` or equivalent for automated pipelines.

### AWS — scoped inline policy

```hcl
resource "aws_iam_policy" "terraform_apply" {
  name        = "terraform-apply-${var.environment}"
  description = "Minimum permissions for Terraform apply in ${var.environment}"

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect   = "Allow"
        Action   = ["s3:GetObject", "s3:PutObject", "s3:ListBucket"]
        Resource = [
          aws_s3_bucket.terraform_state.arn,
          "${aws_s3_bucket.terraform_state.arn}/${var.environment}/*"
        ]
      },
      {
        Effect   = "Allow"
        Action   = ["dynamodb:GetItem", "dynamodb:PutItem", "dynamodb:DeleteItem"]
        Resource = aws_dynamodb_table.terraform_locks.arn
      },
      # workload-specific permissions (VPC, EC2, RDS, etc.) added here
    ]
  })
}
```

### Azure — custom role

```hcl
resource "azurerm_role_definition" "terraform_apply" {
  name        = "TerraformApply-${var.environment}"
  scope       = data.azurerm_subscription.current.id
  description = "Minimum permissions for Terraform apply"

  permissions {
    actions = [
      "Microsoft.Resources/subscriptions/resourceGroups/read",
      "Microsoft.Resources/subscriptions/resourceGroups/write",
      # add only what the workload needs
    ]
    not_actions = []
  }

  assignable_scopes = [data.azurerm_subscription.current.id]
}
```

## LLM Mistake Checklist

- [ ] No secrets in variable `default` values
- [ ] Sensitive variables and outputs marked `sensitive = true`
- [ ] Data sources reading secrets use `ephemeral` (1.10+) or values not passed to resource args that store to state
- [ ] Passwords passed to resources use `write-only` arguments when available (1.11+)
- [ ] State backend has encryption-at-rest enabled
- [ ] State backend has versioning enabled
- [ ] State bucket has access logging enabled
- [ ] `terraform.tfvars` is git-ignored for any file containing secrets
- [ ] CI/CD applies with scoped role, not admin
- [ ] Trivy or checkov runs in the pipeline (not just locally)
- [ ] `checkov:skip` comments include justification
- [ ] `depends_on` is NOT used to sequence unrelated resources just to "be safe" — pass attributes
